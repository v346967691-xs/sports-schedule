## 一、故障：CI 在北京时间 12:00 整开始连续全红

### 时间线（UTC）

| 时间 | 结论 | commit |
|---|---|---|
| 10-19 18:00 ~ 10-20 03:45 | 连续 success | `55553ac` |
| **10-20 04:00** | **failure（分界点）** | `55553ac` |
| 10-20 04:00 ~ 07:30 | 连续 16 班全部 failure | `55553ac` |
| 10-20 07:45 | **success（修复验证）** | `9594a5f` |

**同一个 commit `55553ac`，03:45Z 的 run 成功、04:00Z 的 run 失败 —— 代码没动，只有时间变了。** 这是定位根因的关键证据。

### 根因

`tools/match-notification.test.js` 里有一条断言没传时钟：

```js
// 修复前（第 133 行）
assert.deepEqual(config.kindsFor(match()), ['pre15', 'result'])
```

而 `utils/match-notification-config.js:7` 的签名是：

```js
kindsFor(match, now = Date.now()) {
  if (match.status === 'upcoming') return Date.parse(match.start) > now ? ['pre15', 'result'] : ['result']
```

`now` 的默认值是**真实系统时钟**。而测试文件里：

- `const now = Date.parse('2026-10-20T03:45:00Z')` —— 这个固定值当时是**显式传进去的**，只有这一条断言漏了
- `match()` 的默认 `start` 写死为 `2026-10-20T04:00:00Z`

于是：

- 真实时间 **< `2026-10-20T04:00:00Z`（北京 12:00）** → `start > now` 成立 → 返回 `['pre15','result']` → 断言通过
- 真实时间 **≥ 该点** → `start > now` 不成立 → 返回 `['result']` → **断言永久失败**

### 影响面

失败发生在 **step 6「验证数据链路回归」**（`npm run test:data`）。它是纯本地测试，与云端无关。但 GitHub Actions 一旦某步失败，后续步骤全部 skip：

```
❌ step 6  验证数据链路回归
⏭ step 7–13  网球积分 / 云环境检查 / 各类刷新（全 skip）
⏭ step 14 刷新并推送赛程快照到云端（skip）
⏭ step 15 校验云端快照是否真的新鲜（skip）
```

**结果：赛程快照从北京时间 12:00 停更到 15:46，共 3 小时 45 分钟。**

⚠️ 这个症状和「云端额度耗尽被隔离」几乎一样（都是全红、都是快照停更），但二者可以一眼分开：**同时查另外两个应用的 `SELECT 1`**。本次三个应用（赛程助手 / 闪现诗词助手 / 桃桃语伴）全部正常返回，且赛程助手 `schedule_cache.generated_at` 在 11:31 还在刷新 → 排除额度。

### 引入时间

该测试由 `3b5fdd8`（2026-10-14）引入。当时 `now` 与 `start` 都是**未来日期**，所以一直绿，埋了 6 天后在 `2026-10-20T04:00:00Z` 准时引爆。

## 二、修复方案（`9594a5f`）

### 改动

只有 1 个文件、4 行新增：

```diff
   // 关注时只申请 15 分钟 + 赛果；pre60 必须由「加一轮」入口再授权一次，
   // 否则一次 kickoff 授权只够发一条，另一个必然拿不到额度。
```

## 四、两条排查经验（已写入 WB 侧长期记忆）

1. **Actions 全红时，先看 red 的是哪一步，再谈额度。** step 6 是纯本地测试，它红与云端无关；但因为它排在前面，会把 step 7–15 全部拖成 skip，症状与额度隔离一模一样。判定顺序：① 看失败 step 名 ② 另两个应用 `SELECT 1` 对照 ③ 才看额度。

2. **测试跑绿一次不算稳定。** 本次就是「跑的时候还没到 12:00」所以绿。凡是断言里出现固定日期，必须用远期时钟复跑一遍。

另注：workflow **没有 `on: push`**（只有 `schedule` + `workflow_dispatch`），所以推送修复不会立即触发 CI run，只能等 cron 或 cron-job.org 那一班。别对着 API 干等 push 触发的 run。
