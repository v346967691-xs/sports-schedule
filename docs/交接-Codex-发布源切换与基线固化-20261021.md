### 2.2 逐字节核对 `_verify` 与 master

不用 md5、不用「文件数相等」这种弱判据，直接算 **git blob SHA-1**：对每个文件计算 `sha1("blob " + 字节数 + "\0" + 内容)`，与 `git ls-tree -r d376fb6` 给出的 blob id 比较。

```js
// 可复现脚本（Node）
const fs=require('fs'),path=require('path'),crypto=require('crypto'),cp=require('child_process');
const ROOT='D:/work/wbzone/_verify';
const raw=cp.execSync('git -C D:/work/wbzone/_rel ls-tree -r d376fb6',{maxBuffer:1<<28}).toString();
const files=[...raw.matchAll(/^\d+ blob ([0-9a-f]+)\t(.+)$/gm)].map(m=>({sha:m[1],p:m[2]}));
const relSet=new Set(files.map(f=>f.p));
let same=0,onlyRel=0,onlyVer=0,diff=0;
for(const f of files){
  const abs=path.join(ROOT,f.p);
  if(!fs.existsSync(abs)){onlyRel++;continue;}
  const b=fs.readFileSync(abs);
  const sha=crypto.createHash('sha1').update(Buffer.concat([Buffer.from('blob '+b.length+'\0'),b])).digest('hex');
  sha===f.sha?same++:(diff++,console.log('DIFF',f.p));
}
(function walk(d,base){for(const e of fs.readdirSync(d,{withFileTypes:true})){
  const rel=base?base+'/'+e.name:e.name, abs=path.join(d,e.name);
  if(e.name==='.git')continue;
  e.isDirectory()?walk(abs,rel):(relSet.has(rel)||onlyVer++);
}})(ROOT,'');
console.log({masterFiles:files.length,same,onlyInMaster:onlyRel,onlyInVerify:onlyVer,contentDiff:diff});
```

## 三、三个坑：下面这些看起来像故障，但都不是故障

### 3.1 🔴 在 `_verify` 里跑 `tools/smoke.js` 会报模块找不到

```
Error: Cannot find module '@tencent-ai/workbuddy-cloud-sdk/miniprogram'
  at D:\work\wbzone\_verify\utils\cloud.js:15:47
```

**这是纯 Node 的解析路径问题，不是包的问题。** 原因：

- `utils/cloud.js` 里 `require('@tencent-ai/workbuddy-cloud-sdk/miniprogram')`；
- 小程序侧由微信开发者工具「构建 npm」产出到 `miniprogram_npm/`，运行时按 `miniprogram_npm` 解析；
- 而 `node tools/smoke.js` 是裸 Node 进程，只认 `node_modules`，不认 `miniprogram_npm`。

所以：**`_verify` 没有 `node_modules` → 烟测跑不起来，属预期。** 分工固定为：

| 任务 | 在哪个目录跑 | 原因 |
|---|---|---|
| 单测 / 烟测 | `_rel`（有 `node_modules`） | 需要 npm 依赖解析 |
| 包体审计 | `_verify` | 必须是 LF 口径（`_rel` 被 `core.autocrlf=true` 检出成 CRLF，虚高 2 万+ 字节） |

### 3.2 云 SDK 在发布包里到底有没有？——有，且受版本控制

```
miniprogram_npm/@tencent-ai/workbuddy-cloud-sdk/miniprogram.js   251,522 B  (main)
miniprogram_npm/@tencent-ai/workbuddy-cloud-sdk/package.json         123 B  (main)
```

两条都在 `git ls-tree` 里（**受版本控制**，不是本地构建产物），且都在包体审计的 main 包里。**所以 `_verify` 没有 `node_modules` 完全不影响真机/开发者工具运行。** 这条已写成判据：谁再说「发布源没 node_modules 会挂」，先看这两个文件在不在包里。

### 3.3 `project.config.json` 里仍是 `appid: touristappid`

```
appid: touristappid | projectname: sports-schedule
```

历史每次发版都是这个值，面板上传时带上真实 appid（`wx…`）—— 这是**历史经验，不是文档承诺**，故列为 §5.C 待确认项，**当前不要手改**，改了反而和面板行为打架。
