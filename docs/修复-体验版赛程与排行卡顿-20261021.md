# 体验版赛程与排行卡顿修复

用户反馈：新体验版手机和电脑微信均卡顿，首页基本正常，赛程分类及赛事标签难以切换，排行长时间空白；正式版正常。已阅读 WB 的发布源切换交接，保留 `_verify` 发布约定与现有分包，不修改 SDK、AppID、后台频率或云端数据。

## 已复现与修复

1. `utils/data.js:matches()` 每次被调用都会重新过滤全量比赛。网球等级过滤又逐场匹配完整赛事日历；赛程卡片近期战绩会对双方反复查赛程，导致一次分类/联赛切换测试累计约 148 万次范围判断。现在按赛程数组及周榜日历版本缓存过滤结果，快照或日历替换时重算。返回数组副本，保留比赛对象引用，使实时比分原地更新立即可见，调用者修改数组也不影响缓存。250 赛事仍被排除。
2. 排行 `buildSlide()` 原来只控制 WXML 可见性，实际仍计算并向视图传递全部赛事榜单，且滑过的页面持续累积。现在只构建当前及相邻共最多三屏，其他保留导航占位；离开窗口后释放内容，保留原滚动位置和标签锚点计算。

## 同数据比较

只读获取当前云端 `schedule_cache`、`standings_cache`、`scorers_cache` 各一次。赛程为 2,389 场，数据时间 2026-10-21 10:05 北京时间。用同一份数据、同一台电脑运行修改前后页面逻辑，模拟 `setData` 和分享输出；下列是本地逻辑耗时，不是手机帧率或微信渲染时间。

| 检查 | 修改前 | 修改后 |
|---|---:|---:|
| 赛程足球初次计算 | 766 ms | 29 ms |
| 切至篮球 | 325 ms | 14 ms |
| 切至电竞 | 128 ms | 2 ms |
| 切回足球 | 731 ms | 25 ms |
| 排行初次计算 | 29 ms | 6 ms |
| 排行首屏 setData 字节数 | 271,485 B | 37,475 B |

结果证明这两处负担已消除，但不能代替新体验版手机与电脑微信验收，也不据此声称已定位所有真机空白原因。
