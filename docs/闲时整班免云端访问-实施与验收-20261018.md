# 闲时整班免云端访问：实施与验收

## 结果与边界

在 GitHub 自动任务的首次 WorkBuddy 探测之前加入活动判断。只有上一轮正常运行留下可信的公共活动记录、本轮再次确认官方比分源无活动、没有待补数据且不处于维护／出报窗口，才跳过本班全部 WorkBuddy 访问。

保留每 15 分钟触发、运行期间每 60 秒比分盯场、大快照 90 分钟、历史详情批量 180 分钟。无固定停机时段，不修改微信客户端，也不修改桃桃。

跳过的班次仍执行本地测试、官方源探测及 GitHub 诊断整理。这不等于完全停止所有网络访问，也不会阻止用户自身在小程序中访问数据库。

## 如何判断

1. 从 GitHub Actions cache 恢复上一轮公共活动记录；恢复不访问 WorkBuddy。
2. 记录缺失、损坏、不同代码版本、来自失败任务、时间异常或过期，执行正常云端任务。
3. 有进行中比赛、进入计划开赛前 90 分钟或已过开赛时间仍未开始的比赛，执行正常任务。不会用比赛拖延过久推测它已经结束。
4. 普通日报 06／07、21／22 点以及 S 赛 09／10、14／15 点，连同进入这些窗口前的一班，强制正常执行。延迟和失败重试窗口保留。
5. 健康活动记录最多允许闲时休眠 60 分钟，并不得越过主赛程上次成功生成后 90 分钟的维护点。跳过不会延长记录有效期。
6. 可能空闲时，通过现有足球、篮球、KPL、LOL、ATP/WTA 比分采集器直接检查全部 45 个来源。出现赛中／临近开赛比赛、新结束比赛、已结束比分纠正，或任一来源失败、不完整，执行正常任务。
7. 官方源总探测在独立进程中执行，45 秒超时即终止并回退正常任务，避免慢源站拖住整班。
8. 正常班次结束后，只有关键步骤成功、来源健康、快照新鲜，才允许生成下次跳过的依据；失败班次写入不可跳过的记录。记录保存至 GitHub，不写入云数据库。

GitHub 缓存只是性能优化：缓存失效、被清理、保存失败时，结果是多跑正常班次，不能导致停止刷新。

## 待补数据保护

创建空闲记录时，只在没有活动比赛的情况下额外读取最近公共详情与网球统计，避免忙时扫描所有统计。

- 最近 48 小时足球／篮球／KPL／LOL 完赛详情，复用 `match-detail.needsFetch` 的实际补抓规则，并提前覆盖下一班的 15 分钟窗口。KPL 缺局、LOL 缺胜负／技术统计、赛后壳数据等，阻止闲时跳过。
- 最近 48 小时网球完赛统计，缺失、不完整、球员方向不匹配、核心数据缺少或达到 24 小时校正期，阻止跳过。待定选手按原采集器规则排除。
- 没有待补数据的已确认赛果会随记录保留。下次上游出现未见过的完赛场次或比分改动，立即恢复本班云端任务，给赛果通知与详情补齐留出执行机会。
- 新建赛前提醒依靠上述 90 分钟赛前保护，覆盖 1 小时与 15 分钟提醒；临近开赛的官方源探测也会唤醒任务。

这是保守策略：若源站持续缺统计，会继续正常补抓，可能没有空闲减载收益。不能为了显示“节省”而把这些比赛当作已完成。

## 观测与预期收益

每班 GitHub Summary 会写出“正常执行”或“确认空闲，本班跳过全部 WorkBuddy 请求”，以及判断原因。主动跳过不触发云环境故障告警，也不宣称云端快照刚更新。

真正连续空闲、无待补统计且不在出报窗口时，通常可把该时段每小时 4 班云端访问减少到约 1 班。**这仅是空闲时段的班次变化，不是全日请求或资源点节省 75% 的承诺。** 有赛事、待补数据或源站异常时，仍按原节奏执行。

空闲时实时心跳可以超过 10 分钟；此时应结合任务的跳过结论判断，不能把单独手动执行 `check-cloud.js --live` 的陈旧提示直接当作停服。正常班次仍运行原实时心跳校验，主赛程仍受 90 分钟维护点约束。

按七天记录统计：已跳过班次数、各类正常执行原因、实际数据库请求窗口并集与用户侧访问；资源点仍须用平台真实账单核对。

## 验证

- 全部工具测试 218 项通过，含 11 项新增保护／接线测试。
- 验证缺缓存、换版本、过期、时间异常、日报边界、提醒边界、长时间比赛、源失败、新赛果、比分更正、待补详情和网球统计。
- 通过全部真实采集器路径的模拟 HTTP 测试，确认闲时发现不触碰云端端点；独立验证探测超时回退。
- 本机真实官方源探测：45 个来源健康，发现当前有活动，正确要求正常执行；此探测没有创建云端客户端。
- 本机公共云端记录读回测试：主快照到维护期时，正确拒绝生成可跳过记录。
- 工作流 actionlint 与差异格式检查通过。

实现后的首个完整自动班次及后续自然空闲班次结果，分别据实记录；本地测试不能代替自然空闲时段的线上观测。

## 运维入口

- GitHub 手动运行工作流时，勾选 `force_refresh`：绕过闲时判断执行本班云端任务。外部定时器不需要修改。
- 仓库 Actions variable `SYNC_IDLE_SKIP_ENABLED=false`：关闭本优化，恢复每班执行。默认启用。
- 主实现 `tools/activity-gate.js`；公共记录 `.workbuddy/activity-plan.json`，仅缓存公共赛程 ID、状态、时间、赛果与版本标识，无用户、订阅凭据或令牌。
- GitHub cache prefix `activity-plan-v1-<代码版本>-`，每个正常班次单独保存；闲时跳过的班次不重新保存，不会滑动续期。
